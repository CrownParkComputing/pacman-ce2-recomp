## Completion-query bottleneck and shadow-stack recovery

The 30 FPS timing build records 450 `vkGetSemaphoreCounterValue` calls taking 2645.207 ms over 150 frames. GNM submission-gate waits total 2645.671 ms and VideoOut buffer-label waits total 1750.824 ms; these categories overlap and must not be added. Present/acquire/frame-fence calls total only about 44 ms. Read-only LLDB captures the graphics thread in `GnmDriver::WaitGpuIdle` and GPU command processing in a semaphore-counter query during submission. Evidence: `out/android-wait-timing-20261115-122030/wait-timing-verification.json` and the earlier `pacing.txt` in the reduced-background trial.

`TEMPEST_VK_DEFER_COUNTER_REFRESH=1` skips eager post-submit queries. Explicit timeline waits publish only their successfully waited tick using atomic maximum; resource reuse and deferred guest-label retirement retain their checks. The first device comparison reduces counter queries to 146 calls / 1626.677 ms over 199 frames, with 39.8 FPS and a live HUD interval advancing 4.70 seconds in 7.061 seconds. The original counter behavior remains available with the flag unset or 0. A pool retry also now observes refreshed completion rather than a stale copied local value.

The next iteration polls only a needed tick with `vkWaitSemaphores(timeout=0)` for scheduler retirement and pool demand, publishing completion only on success. Timeout defers reuse; it does not loop, flush or infer newer work complete. The existing tick-cache regression covers real readback retirement, failed waits, 64-bit ticks, concurrent publishers and deterministic poll interleavings. Native rendering remains valid, but R5 device performance regresses to 30 FPS / 0.503× speed: 300 supposedly nonblocking polls take 2633 ms over five seconds. The previous deferred-query APK was restored at 38.1 FPS / 0.639× speed. Evidence: `out/android-targeted-poll-786c2473-run/targeted-poll-verification.json` and `out/android-restored-defer-e22c6d42/rollback-verification.json`.

### Matching KGSL driver defect

Mesa's [upstream fix e984ef29](https://github.com/chaotic-cx/mesa-mirror/commit/e984ef29) explains that KGSL interprets a zero wait timeout as an indefinite wait. The fix reads the retired timestamp instead when the deadline has expired. Static inspection confirms that R5 has the old direct-wait path; the separate local Mesa 26.2.1 library also lacks the fix. Neither library is an appropriate basis for testing nonblocking Vulkan polls.

The [Standard Adreno 6xx/7xx Turnip release dated November 11](https://github.com/The412Banner/Banners-Turnip/releases/tag/v27.0.0-20261111-r2) was tested as a driver-only replacement. Its ZIP matches the publisher's SHA-256 `bcc118d8a8bb4206f2012c1941252f46eb92b3da5cc579af368ac56fb2769271`; the embedded ARM64 library SHA-256 is `472c1d0b4b415229facc3015e73dd4f5c8298cdbc7207d5df8b60edfda64039e`. Disassembly verifies that zero/expired deadlines use `READTIMESTAMP_CTXTID` with `KGSL_TIMESTAMP_RETIRED`, returning success or timeout after comparing the retired timestamp. Positive waits retain the wait ioctl. The first replacement APK has identical runtime bytes to the targeted-poll candidate; only its driver, provenance and signatures change. Live process mappings and the extracted app-private library hash verify that the fixed driver is loaded. Targeted polls now take 3.065 ms total for 568 calls per five seconds, rather than 2633 ms for 300 calls. The title reaches 59.8 FPS, and the user confirms normal gameplay speed. Evidence: `out/android-fixed-driver-20261115/driver-fix-evidence.json`, `driver-only-ab.json` and `out/android-turnip27-12ec1aba/`.

At the user's request, Android now defaults to the complete decorative background (`TEMPEST_CE2_REDUCED_BACKGROUND=0`), retaining 720p, native-copy and the working targeted-poll policy (`TEMPEST_VK_DEFER_COUNTER_REFRESH=1`). Restored-background APK SHA-256: `a10cb43f5ecfd21efcc4f56ce50c520e124191a9d81a4632ec8572075f86f144`. Its installed package and live driver hashes match. `out/android-background-restored-a10cb43f-run/final-own-screen.png` visibly shows the restored perspective grid around Tutorial 1-4; focus is verified before and after capture. The hint overlay measures 46.8–47 FPS, the title 59.8 FPS; no new active-gameplay clock interval was recorded after restoration, so these are not a universal 60 FPS claim. Audio ports report no starvation. One initial black startup recovered with a cold restart of the same APK; the log included swapchain acquire failures, and its underlying cause is unresolved. Save data was preserved.

Crash evidence at `out/android-reduced-background-20261115-120100/offline-crash-audit.json` places the fault exactly 16 bytes below a guarded 4 MiB mapping, matching FEX's shadow call/return stack. The pinned FEX Linux and Windows frontends explicitly recover this normal guard-wrap condition.
